# Release and hosting

Use three connected surfaces: **GitHub for the benchmark source and protocol, GitHub Pages for the visual result gallery, and Colab for trying the environment.** Host long videos on Bilibili/YouTube and versioned runtime/data artifacts separately. This static project page needs no application server or new server purchase.

GitHub Pages publishes static HTML/CSS/JavaScript. It cannot host the native Unity Player or keep evaluation sessions running. The [public replay notebook](https://colab.research.google.com/github/P90-RushB/robopaint-bench/blob/main/notebooks/GoldenGate_Record_Colab.ipynb) starts the Linux Player in a visitor's GPU runtime, replays a selected model's saved actions and exposes AgentArk's viewer through the link printed in step 7; it needs no model API key. The separate evaluation notebook calls a model provider using the visitor's credentials. Model inference charges and Colab resource policies are independent of the website. [GitHub Pages overview](https://docs.github.com/en/pages/getting-started-with-github-pages/what-is-github-pages)

The repository includes the complete selected website image set: **69 PNGs** comprising Golden Gate’s 33 canvases, reference and two robot recording frames, plus Pelican’s 33 canvases. After installing `requirements-site.txt`, a fresh clone can run `python scripts/build_site.py --output local_save/site-preview-01` without a private catalog or separate media ZIP. The builder verifies the images against the tracked hash manifests. Full videos stay on Bilibili; the old 12-second local excerpt is excluded.

## Prepare the public release

1. Keep the benchmark protocol, version lock, reproducible inputs and evaluator wrapper in Git. Preserve the distinction between task submission reward, visual quality assessment and observed model behavior.
2. Review the gallery's selected canvases and provenance across both independent tasks. The **69 curated website PNGs** are approved for inclusion in Git and versioned alongside the site: 36 Golden Gate images and 33 Pelican canvases. Preserve their notices; inclusion does not apply the code's Apache-2.0 license to them. Raw results, request bodies, encoded image dumps, full recordings, logs, local manifests and credentials remain outside Git.
3. Check the actual access state of the GitHub repository and locked runtime dataset. A notebook link cannot grant private repository or dataset access. The installer supports Hugging Face's normal authentication; run a fresh authorized download check before advertising anonymous access. Its revision/hash lock must stay immutable.
4. Enable GitHub Pages for the repository and manually run the supplied deployment workflow. It builds from checked-in images and needs no media-archive URL or approval phrase. Check the resulting project URL, relative assets, mobile gallery, notebook link, source links and attribution. A custom domain is optional. Pushing the source alone does not deploy Pages.
5. Validate one fresh Colab session through installation, rendering, preparation and a small explicitly authorized model evaluation. Archive the exact package freeze and graphics log. The current offline notebook checks are not a substitute for this hosted runtime check.
6. Verify the published links in `benchmarks/results/model-videos.json` and test switching models in the single shared Bilibili player. All 11 Golden Gate recordings and 11 independent [Pelican recordings](../benchmarks/results/pelican-videos.json) are linked. The explanation video remains pending; show its status plainly.
7. Tag the release and make an archival snapshot if desired. Update the citation with the real release DOI only after an archive exists; do not invent a DOI, paper acceptance or quality ranking.

Approval to include selected website images does not authorize uploading other evaluation data. Review the exact files and destination before changing access or publishing additional artifacts. A release should preserve the original runs and any recovery segments; staging public copies does not make ignored evidence disposable.

## Keep future results comparable

Accept complete manifests, exact model/provider/effort, case/seed, all attempts, action records, input hashes, runtime versions, output-budget limitations and visual assessment evidence. Separate new standard runs from mechanics variants and arbitrary drawings. Provider model aliases and SDKs can change; record the actual version/date and constraints instead of relying only on a display name.

Keep the 11-model Golden Gate release fixed. Keep the independent text-goal Pelican collection separately versioned: 11 models, 33 attempts, 603 actions and 4× videos. Its checked records are pinned to HF revision `b16fb52e866ce6a33c52e287f04bfe4a77964453`; no Golden Gate ranking is transferred. Add a scored leaderboard when an assessment protocol and reviewer evidence are available; a gallery of finished works is useful evidence without pretending that submission reward measures art quality.
